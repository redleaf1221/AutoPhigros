# human-like 规划器（草案）

> 状态：**草案**，还没写代码。代码落在 `src/algorithms/human.py`（待建）。
> 这份文档只回答"这个算法长什么样、凭什么它不会重蹈旧三个的覆辙、怎么算它做对了"。

## 0. 一句话

**规划的对象不是"按哪些点"，而是"每根手指怎么动"；每次动作判掉了谁，由
`src/algorithms/judging.py` —— 同一份、已经与实机逐音符对齐过的判定规则 —— 当场算出来，
规划器照单认领。**

## 1. 为什么另起一个

旧三个算法共有一个前提：**先决定"这一次按下是为哪个音符按的"，再指望游戏也这么判。**

而 `JudgeControl::CheckNote` 是"按下那一帧，在够得着的候选里挑 `selection_metric` 最小的
那个"—— 一次按下只判**一个**音符（这条的来龙去脉写在 `judge_taps` 的注释里：第一版按
"全部判掉"写，Credits IN 上凭空多出 80 个 Good）。**判到谁不由意图决定。**

于是"意图 = 后果"不成立的地方就长出了两样东西：**蹭键**与**级联**。它们不是三个算法的
三个 bug，而是那个前提的必然产物。实测（`夢の降る日に IN`，geometric，送达准时）：

| 症状 | 现场 |
|---|---|
| 6 个蹭键 | 全部由 **drag / flick 的起手**抢走（按住 24–144ms 的"按下"），被判成 Good(−180/ −119/ −122/ −118ms) 与 Bad(−205/ −209ms) |
| 级联 | 线 21 那串 TAP 被抢掉一个之后，后面每个点按都去判**下一个**音符，整串后移 |
| 丢音 | 线 0 尾段 `DRAG @ 38.654s` 没人管（窗口里最长只有 0ms 有手指在位） |

旧算法要"修"这件事，只能**在几何上做文章**：把一个起手挪开，或者给同一个音符再多按一次。
而挪开一个起手的落点，未必能让它放开**另一条线上**的目标 —— 这是拿几何去解一个**逻辑**
问题。两条都试过、都被实测否决，已撤回。

所以：**不去动 `conservative` / `radical` / `geometric` 了。**
它们留着做对照 —— `judge.py --compare logs/2026-09-27_19-49-47.log` 那条验收线
（1156/1156、0 处不一致、951099 分）仍压在 radical / geometric 身上。

## 2. 三条纪律

1. **判定规则只有一份。** 规划器不重写 `tap_window` / `selection_metric` / `deviation` /
   `verdict_of` / drag 窗口 / flick 起手判据里的任何一条。它直接调 `simulate`。
2. **动作先问裁判。** 每个候选动作提交前，用真裁判算它的后果；**后果就是规划器记录的事实**，
   不是规划器的猜测。这样"规划时的判定"与"体检时的判定"不存在第二份实现，也就不存在
   "错一点，以后 debug 痛苦 100 倍"。
3. **停止条件是裁判说干净。** 不是"我把音符排完了"。

第 2 条之所以做得到，是因为裁判很便宜：**1243 音符的整谱重放（`simulate`）30 毫秒**
（实测；`--no-cache` 跑一张谱的 3.6s 里，绝大部分是规划与覆盖判据）。规划器可以在一张谱上
跑几百轮"改一点、重放一遍"。

## 3. 判定给规划的两条事实

| 类别 | 音符 | 游戏怎么判 | 规划含义 |
|---|---|---|---|
| **按下类** | TAP、HOLD 的头、FLICK | 手指 `phase == Began` 那一帧 `CheckNote` 挑一个 | **一次按下只判一个**：每个这样的音符都要有"属于它"的一次按下，落点与时刻都得对 |
| **路过类** | DRAG、HOLD 的身体 | 逐帧比位置（drag 窗口 ±0.1s，hold 身体宽限 3 帧） | 手指在窗口里落在容差内就判，**不需要按下**；一根手指可以顺手判掉一串 |

这条分界正是"人类为什么不会打成旧算法那样"的根据：人类**按下的是他瞄的那个，路过的是他顺手
碰到的**。旧算法把路过类的合并思路（判定区求交）也套到了按下类上，于是出现了"一次按下同时
判掉一片"的幻觉 —— 那在实机上不可能发生。

## 4. 人类模型

### 4.1 手与指

- **2 只手 × M 根手指**（默认 M = 2，共 4 根）。依据：实测**全部 17 张官谱**（含 AT）里
  "按下类 + 按住中"的峰值同时需求 **≤ 4**：

  | 谱面 | 音符 | 峰值同押 |
  |---|---|---|
  | Retribution | 1502 | 4 |
  | PRAGMATISM | 1156 | 4 |
  | PRAGMATISM | 999 | 4 |
  | ENERGYSYNERGYM | 580 | 4 |
  | BRAINHACKER | 372 | 4 |
  | 其余 12 张 | — | ≤ 3 |

- 每根手指是一个独立的指针（pointer id 固定），**不许瞬移**。
- 左手所有手指的横坐标恒 ≤ 右手（不交叉）—— 从搜索空间里就排除掉。

### 4.2 运动学

- **速度上限** `FINGER_SPEED`（虚拟单位/秒，屏宽 16）。初值 80（横穿整屏 0.2s），待校准。
- **速度剖面**用最小抖动（或梯形），峰值 ≤ 上限；移动中每 8ms 一个 MOVE。
  静止时自然没有事件 —— `EventTrack` 会压掉同一指针同一坐标的 MOVE，这本来就是真实手指的行为。
- **按下之前必须到位**：为了在 `t` 按下，手指得在 `t − 行程时长` 出发。这条既是"人类不会
  瞬移"的硬形式，也顺带消掉了所有横向跨度极大的按下。
- 按下后**停够一帧**（`MIN_DWELL_MS = 20ms`）再抬。逐帧判定的世界本来就要求这个，而它正好
  压在人类点按时长（40ms 上下）的区间里。

### 4.3 手位与交替

- **就近**：能按时到位的手指里，挑行程最短的。
- **交替**：同一区域相邻间隔 < `STREAM_GAP`（初值 120ms）的一串 TAP，交替分给同手的两根
  手指（或左右手），像人打连音那样。这也是"像人"最显眼的一条。
- **别横跳**：同一根手指连着两次大跨度的反向移动，在代价函数里罚分。

### 4.4 按住跟线 / 甩

- **HOLD 全程跟线**：手指跟着 `line.point_at(t, offset)` 投到屏幕上的点走（每 8ms 采样）。
  判定本来就是逐帧量横向偏差，不跟就跟丢；人类也是盯着线走的。
- **FLICK 要甩**：到位后甩出 `flick_radius`，得让 `isNewFlick` 成立（起手判据照抄裁判的
  `FLICK_JUMP`）。

## 5. 算法

三层：**风格约束在最外层（硬），裁判在最内层（真）。**

### 层 1 —— 可行动作集（硬约束）

规划器**只生成**满足 4.1–4.4 的动作。违反风格约束的候选根本不进搜索空间 ——
所以结果天然"像人"，而修复只可能发生在判定层面。这一层是"人类不会这么打"的**构造性**保证，
不是事后检查。

动作单元 `Stroke`：

```text
Stroke(
    finger,      # 哪根手指
    kind,        # 移动 / 点按 / 按住 / 甩
    path,        # [(t_ms, position), …] 采样轨迹，满足速度与加速度上限
    target,      # 这次动作**声明**瞄着哪个 slot（可以为空 = 纯路过）
)
```

### 层 2 —— 初稿

按时间序扫一遍音符：按下类按 4.3 选手指、按 4.2 倒推出发时刻、生成轨迹；路过类先不专门安排
（等着被路过）。此时它的水平大致相当于"一个手很稳但没算过判定的玩家"。

### 层 3 —— 裁判在环修复

把草案编译成 `PlanResult`（**`.psap` 格式不变**，所以镜像、触控后端、`render.py` 都不用改），
交 `simulate`，读成绩单，按症状挑算子：

| 症状（裁判原话） | 算子 |
|---|---|
| 丢音（`report.lost`） | ① 给这个音符补一次按下；② 若同刻有手指路过它的判定区，把那段轨迹挪近一点 |
| `Graze(stolen=True)` | **不是错误，是信息**：这一次按下判掉的是它 → 记成已判，把原计划那一次按下删掉（去冗余）；或把目标那一次提前，让意图赢回来 |
| 掉档 Good / Bad | 把那次按下的时刻往音符的判定时刻挪（1ms 栅格） |
| 覆盖不足（窗口里没有整帧在位） | 让手指在窗口里多停 ≥ 一帧 |

每轮重放一遍整谱（30ms）。**目标函数按字典序**：

1. 丢音数（先降到 0）
2. 非 Perfect 数
3. 事件数（一个 MOVE 就是一次注入，见 `docs/impl.md`）

连续两轮无改进就停，**把残余如实报出来**（`stats` + `warnings`），不假装干净。

> **蹭键这个概念在新算法里会消失**：它描述的是"意图与后果不一致"。意图若从后果里读出来，
> 就没有不一致可言 —— 一次按下判掉了谁，那就是它判掉的，记下来接着排后面的。

## 7. 解不出来的时候

诚实优先，绝不静默：

- 峰值同押 > 手指数 → 报"这里需要 N 根手指，模型只有 M 根"，出尽力而为的结果。
- 够不着（速度上限太紧） → 报"行程不够"，并打出那一处的时间与位置冲突。
- 修复不收敛 → 打出残余的丢音 / 蹭键清单，`planner.py` 里显示，不吞掉。

## 8. 验收

### 8.1 硬指标

- `python src/judge.py --planner human`：17 张全部 `lost == 0`。这是**目标**；达不到就是真无解，
  按 §7 报出来。
- `--compare` 的老账不回归（radical / geometric 一个字都不许变）。
- 风格断言进 `src/tests/human.py`，每条都要求"把实现改坏它就红"：
  手指数 ≤ 配置、相邻事件位移 ≤ `FINGER_SPEED × Δt`、每次按下的落点偏差、静止不发事件、
  左右手不交叉。

### 8.2 像不像人（看得见 + 量得出）

- `python src/render.py plans/xxx.psap` 出片，人工看一眼：手指是在"走"还是在"闪"。
- 量化：每根手指的横移总量/秒、起手次数/秒、同时按下的手指数分布、抬起-按下间隔分布。
  规划器在 `stats` 里打出来。

## 10. 与旧算法的关系

- 不动 `conservative` / `radical` / `geometric`；`--compare` 仍压在它们身上。
- 新算法**不共享**它们的分配器，只共享 `chart` / `geometry` / `track` / `judging` 四层地基。
- `radical` 在 16 张谱上 100% 说明"规则吃透了就能打满"。新算法要赢的不是满分，
  而是**每一处动作都能用人类的手解释**。
